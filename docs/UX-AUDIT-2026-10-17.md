# Garage interface audit, 2026-10-17

## Scope and result

Reviewed the desktop and browser shells, Home, track libraries, preset and group
collections, customization, pagination, saved-image behavior and input navigation.
Inspected the supplied screenshots and a contact sheet from the supplied video.
Tests distinguish the browser edition's file permissions from desktop capability.

The main problem was task hierarchy rather than decoration: collection commands,
selection controls and commit actions competed for attention. Repeated track
navigation and hidden exact-appearance favorites added unnecessary steps.

| Dimension | Engineering assessment | Evidence and remaining limit |
| --- | --- | --- |
| Accessibility | 3/4 | Named native controls/dialogs, tile arrow navigation, explicit save shortcut, focus scope and reduced motion. Physical controller hardware remains untested. |
| Performance | 3/4 | No new production dependencies; lazy model decoding, bounded part caches and image loading preserved. Lobby polling is bounded and avoids overlapping requests. First uncached extraction still costs time. |
| Responsive layout | 3/4 | Measured complete rows, narrow defaults, contained previews, equal category geometry and fixed footer checked at 390/740/1440px. Very short windows still scroll content. |
| Theming | 3/4 | Selection stays olive/lime; positive teal-green Save is distinct. Existing app tokens remain; some older hardcoded colors remain outside the changed editor. |
| Interaction patterns | 3/4 | One Tracks hub, four main-menu choices, tile-local stars, skipped single-choice refinements, save-in-place and named lobby actions. No added confirmation pages. |
| Total | 15/20, good | Qualitative engineering audit, not accessibility certification. |

## Prioritized findings and changes

- **P1, selected favorites disappeared:** `AppearanceChoice` excluded selected
  items and early hierarchy steps. Every represented look now has its star on the
  tile. The detached star above pagination is removed. Favorites opens saved
  exact looks directly; the tooltip identifies the represented look.
- **P1, pictures cropped:** thumbnail spans inherited a two-line text clamp and
  grid text layout. `presets/editor.css` gives image spans their own flex geometry
  and contained rendering. Category images and sticker symbols share dimensions.
- **P1, choosing looked like committing:** numbered refinement steps and guidance
  explain the next choice; single-choice refinements are skipped. Selection uses
  quiet lime outlines and Save uses a green check. Successful saves keep the
  editor open with a Saved state and a new baseline.
- **P1, incomplete input support:** spatial keyboard arrows and optional standard
  controller navigation follow actual rendered columns. PageUp/PageDown and
  LB/RB change pages, Ctrl+S and Menu/Start deliberately save an enabled editor.
  Controller A never activates save/delete. Hidden/unfocused Garage ignores input.
- **P1, preview ownership unclear:** the BepInEx renderer and companion endpoints
  are removed. Saved image reads actual game PNGs and refreshes on file revisions.
  It is labeled as the last game render when selections differ. A closed game
  cannot generate a new Unity image; independent local 3D still works.
- **P2, navigation scattered:** Tracks contains Discover groups, My groups and My
  tracks. Discover has no export/selection commands. The browser keeps supported
  track tabs and explicit file permission. Home uses the supplied garage artwork
  beside Quick Setup, Presets, Tracks and desktop Lobby.
- **P2, pagination arbitrary:** complete rows support Show all and a custom
  positive integer. Preferences are scoped to each collection and resize/page
  clamping are tested. Smaller windows default to fewer rows.
- **P2, large modal blank space and narrow overflow:** modal height follows content
  up to the viewport limit. Category buttons are equal, Original/Modded is centered,
  preview toggle lives in the header, and close/save remain reachable. Wide screens
  open 3D by default; narrow windows start collapsed.
- **P2, lobby copying took too many in-game steps:** the new Lobby page reads real
  occupied slots, shows named parts and copies one selected setup into All presets.
  Runtime verification is recorded separately in LOBBY.md.

## Verification boundary

Unit/component tests cover favorites on a selected one-variant tile, automatic
refinement skipping, custom/all rows, responsive focus movement, safe controller
commands, save-in-place and Quick Setup editing with the game closed. Browser
checks measured equal category widths, zero picker horizontal overflow and a
visible footer at 390 and 740px. The large view renders independent 3D by default.

Real native lobby read/copy/icon-generation/cleanup passed in an online room with
CPUs, preserving the original library and other profile data. Human remote-player
copying, race-return transitions and physical controller hardware remain separate
runtime checks. No website deployment or public release is implied by this audit.
